- 구현: `src/app/heatmap-canvas.tsx`(그리기 · 이벤트), `src/app/heatmap-layout.ts`(배치 · 색 · hit test, 테스트 있음)
- 데이터: `sgg_monthly_counts`(derive가 매일 재계산), `src/server/queries/heatmap.ts`

## 이 차트가 답하는 질문

"수도권에서 **지금 그 지역치고** 거래가 활발한 곳은 어디인가?" — 시장 분석이 아니라 지역 선택 입구다 (docs/03 C). 칸을 누르면 그 지역 페이지로 간다.

## 1차안을 버린 이유 (사용자 피드백, 2026-10-19)

1차안: 83개 시군구 × 2006~현재 월 전체(2만 칸), 색 = 월 거래 수 절대값(파랑 7단계), 높이 860px.

| 문제 | 원인 |
|---|---|
| 파란 벽 — 패턴이 안 읽힌다 | 칸 2만 개 + 칸 사이 흰 틈이 격자 무늬를 만든다 |
| 행마다 가로 줄무늬만 보인다 | 절대 건수 → 큰 지역(노원 · 남양주)은 늘 진하고 작은 군은 늘 옅다. **지역 크기를 보여 줄 뿐** |
| 진입 화면을 덮는다, 글자가 9px | 83행 × 20년을 한 화면에 |

## 구성 (2차안)

| 요소 | 결정 | 이유 |
|---|---|---|
| 행 | 시도 탭(서울 25 · 인천 11 · 경기 47), 행 18px · 글자 11px | 한 번에 보는 행을 줄여 읽히게 |
| 열 | 기간 3년(기본) · 10년 · 전체 | 입구로는 최근이 중요. 10년이면 2022 거래 절벽이 한 덩어리로 보인다 |
| 색 | **그 지역 평소 대비 배율**. 평소 = 직전 60개월 월평균(이동 평균, 그달 제외), 이력 12개월 미만이면 계산 안 함 | 지역 크기를 지우고 "그 지역치고 활발한가"를 비교 가능하게 |
| 색 램프 | diverging: 파랑(적음) 3단계 ↔ 회색(평소 ±10%) ↔ 빨강(많음) 3단계, 경계는 배율 대칭(0.5↔2, 0.7↔1.4, 0.9↔1.1) | 기준선 양쪽의 극성(polarity) — dataviz 규칙: 두 색상 + 회색 중간, 양쪽 같은 단계 수. 빨강 = 활발(국내 관례 · 열기) |
| 최근 2개월 | 35% 불투명도 + 범례 "집계 중" | 신고 기한(30일) 전이라 배율이 낮게 나와 "급랭"으로 오독된다 |
| 툴팁 | "거래 377건 · 평소 247건의 1.52배" | 배율만으로는 규모를 알 수 없다 — 원래 건수를 함께 |
| 계산 위치 | 이동 평균은 클라이언트(순수 함수 + 테스트) | 2만 개 숫자의 가벼운 표현 변환. 서버에서 하면 payload가 두 배 |
| 상호작용 · 접근성 | hover: 이름 칸 강조 + 칸 테두리 + 툴팁, click: 지역 페이지. 키보드 경로는 아래 "지역에서 찾기" 목록 | |

## 결정: ECharts → Canvas 직접 구현

docs/03 C 조건 3: "ECharts로 먼저 구현하고, 직접 구현은 ECharts의 한계가 실제로 확인된 후 검토한다."

ECharts 버전(커밋 `1d85a25`)을 먼저 만들어 쟀다. 진입 화면 TBT **43 → 259ms**, Performance 99 → 91 (Lighthouse 모바일, 3회 중앙값). 원인을 나눠 보면:

| 비용 | long task |
|---|---:|
| ECharts 청크 실행 (612KB, gzip 206KB) | 117ms |
| `setOption` — 2만 칸을 그래픽 객체로 만드는 처리 | 202ms |

그리기 방식(칸 테두리 제거, 점진 렌더링)을 바꿔도 TBT가 그대로였다 — 비용이 픽셀이 아니라 라이브러리 로드와 데이터 객체화에 있다. 화면 근처에서만 만드는 지연 로딩도 효과가 없었다 (히트맵이 모바일 첫 화면 바로 아래라 곧바로 시작).

히트맵은 사각형 격자라 직접 그리기가 단순하다: `fillRect` 2만 번은 수 ms. 직접 구현으로 바꾸고 다시 쟀다 (1차안 기준, 2차안도 TBT 43ms · Performance 99).

| | ECharts | Canvas |
|---|---:|---:|
| 진입 화면 TBT | 259ms | **40ms** (히트맵 없을 때 43ms) |
| Performance | 91 | **98** |
| 히트맵 코드 (gzip) | 206KB (ECharts) | **2.8KB** |

구현 요점: 바탕 캔버스(데이터 · 크기가 바뀔 때만)와 덮개 캔버스(hover 표시만)를 나눠, 마우스 이동마다 2만 칸을 다시 그리지 않는다. `devicePixelRatio`만큼 크게 그려 고해상도 화면에서도 선명하게, 범례 · 툴팁은 HTML. Pretendard가 늦게 오면(`document.fonts.ready`) 글자를 다시 그린다.

잃은 것: ECharts의 aria 자동 설명, 내장 툴팁 위치 계산, 확대 · 축소. 이 차트에는 필요 없거나(확대) 직접 구현이 짧았다(툴팁).

## 데이터: 사전 집계

원본(514만 건) 집계는 로컬 792ms · 운영 Neon 3.46s. 진입 화면마다 돌릴 수 없어 `sgg_monthly_counts`(20,486행, 1.9MB)를 derive가 매번 재계산한다(+2.1s). 원본도 하루 한 번 갱신되므로 신선도 손해가 없다. 대안이었던 `use cache`는 캐시가 비었을 때(첫 요청, 배포 직후) 3.5초가 그대로 드러나 택하지 않았다.
