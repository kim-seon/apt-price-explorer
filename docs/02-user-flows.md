# 02. Core User Flows

- Status: Accepted
- Date: 2026-10-12

## Screens (MVP)

```text
① 검색/진입   /
② 지역 페이지  /regions/[code]      탭: 단지 목록 | 통계 | 거래 탐색
③ 단지 상세    /apartments/[id]
```

초기안의 "지역 내 단지 목록"과 "지역 통계"는 같은 지역을 보는 다른 관점이므로 하나의 지역 페이지 + 탭으로 통합했다.

---

## F1. 단지명으로 바로 찾기

```text
검색창 입력 → 자동완성 → 단지 선택 → ③ 단지 상세
```

- 데이터: 단지명, 법정동, 시군구, 최근 거래일
- 상태: 결과 없음, 동명 단지 다수 (목록에 지역 필수 표시)
- Interaction 이슈
  - 한글 IME 조합 중 요청 방지
  - debounce
  - stale response 방지
  - 키보드 탐색 (combobox 접근성)

## F2. 지역에서 단지 고르기

```text
시도 → 시군구 → (법정동) → ② 지역 페이지 [단지 목록] → 정렬/필터 → ③ 단지 상세
```

- 데이터: 단지별 집계 (최근 거래가, 기간 내 거래 수, 건축년도, 대표 면적)
- 상태: 최근 거래 없는 단지, 오래된 단지
- Interaction / 성능 이슈
  - 단지별 집계 쿼리 비용
  - 뒤로가기 시 정렬·필터·스크롤 위치 복원

## F3. 단지 상세 탐색 (핵심)

```text
진입 → 요약 → 면적 타입 선택 → 가격 추이 차트 → 기간 조정 → 거래 내역 테이블 → 해제 거래 포함/제외
```

- 구성: 요약 카드 / 면적 타입 탭 / 가격 차트(개별 거래 산점도 + 월별 중위가 선) / 월별 거래량 / 거래 내역 테이블
- 데이터: 단지 거래(수백~수천 건), 면적 타입별 월별 집계
- 상태: 거래 1~2건뿐인 면적 타입, 해제 거래만 있는 월
- Interaction / 성능 이슈
  - 필터 변경 시 차트·테이블 동시 갱신과 transition state
  - 산점도 포인트 수 증가 시 렌더링
  - 차트 기간 선택 ↔ 테이블 동기화

## F4. 지역 단위 탐색 (보조)

```text
② 지역 페이지 [통계] → 월별 거래량·중위가
              [거래 탐색] → 복합 필터 → 대량 테이블 → 행 클릭 → ③ 단지 상세
```

- 데이터: 지역 월별 집계, 지역 전체 거래(수만 건)
- 대량 테이블 성능 사례의 중심
  - virtualization vs pagination
  - server-side sort
  - 다수 필터 파라미터의 URL 동기화
  - 깊은 스크롤

## F0. 공유·재방문 (공통)

- URL만으로 필터 / 탭 / 면적 타입이 재현된다.
- 잘못된 파라미터(없는 단지 ID, 범위 밖 기간)를 처리한다.
- 데이터 기준일을 표시하고, 최근 1~2개월은 신고 기한 때문에 거래가 추가될 수 있음을 안내한다.

## Decisions

| # | 항목 | 결정 | 이유 |
|---|---|---|---|
| 1 | 화면 구성 | 4개 → 3개 (지역 페이지 탭 통합) | 같은 지역의 다른 관점, 이동 단순화, 구현 범위 축소 |
| 2 | 차트 ↔ 테이블 연동 | MVP: 차트 기간 선택 → 테이블 필터링. hover 양방향 하이라이트는 Phase 3 (→ 03에서 확장: brush가 요약 카드·URL까지 갱신, 테이블 → 차트 단방향 hover는 MVP 포함) | 기간 연동은 Product Frontend 역량을 잘 보여줌. 양방향 하이라이트는 상태 동기화 복잡도 대비 가치가 낮음 |
| 3 | 면적 표기 | 전용 기준 "전용 84㎡ (25.4평)". 평형(공급) 표기 안 함 | 원천 데이터에 공급면적 없음. 부정확한 정보 표시 방지 |
| 4 | 차별화 기능 | 해제 거래 표시, 신고가 표시 MVP 포함 | 데이터 추가 비용 작음, 실수요자에게 의미 큼 |
| 5 | 단지 상세 기본값 | 면적 타입: 거래 최다 타입 / 기간: 최근 5년 | 초기 payload 제한, 가장 관심이 많은 타입 우선 |
