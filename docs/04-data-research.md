## 규모 추정 (⚠️ 적재 후 실측으로 대체)

### API 호출 수

- 수도권 시군구 코드: 서울 25 + 인천 10 + 경기 약 40 (일반구 단위) ≈ **75~80개**
- 기간: 2006-01 ~ 2026-09 ≈ **249개월** (⚠️ 제공 시작 시점 확인 필요)
- 기본 호출 ≈ 80 × 249 ≈ **약 2만 회** (+ 1,000건 초과 월의 추가 페이지)
- 개발계정 10,000회/일 기준 **약 2~3일**에 초기 적재 가능. 운영계정 전환 시 단축.

### 행 수와 저장 용량

- 수도권 아파트 매매: 연 약 15만~40만 건 (시장 상황에 따라 변동 큼). 2024년 1~5월 약 8.1만 건 보도.
- 20년 누적 ≈ **약 400만~600만 건** 추정
- 행당 약 300~400 bytes (텍스트 필드 포함) → 테이블 약 1.5~2.5GB, index 포함 **약 2~4GB**
- 관리형 PostgreSQL 무료 티어(수백 MB 수준)를 **초과할 가능성이 높다** → 6~7단계 인프라 비교의 입력값

## 설계에 영향을 주는 발견

1. **`aptSeq`(단지 일련번호)가 있다.** 이전 가정("단지 ID 없음 → 이름 기반 정규화")이 바뀔 수 있다. 다만 다음을 실제 데이터로 확인해야 한다.
   - 과거 데이터(2006년대)에도 채워져 있는가
   - 같은 단지가 기간 내내 같은 값을 갖는가
   - 하나의 값이 여러 단지를 가리키는 경우는 없는가
   → 확인 결과에 따라 정규화 작업은 "주 식별 로직"에서 "`aptSeq` 품질 검증 + 예외 처리"로 축소될 수 있다.
2. **해제 거래가 원본에 포함되어 있다** (`cdealType`). 해제 표시 기능은 추가 수집 없이 가능.
3. **동 정보는 등기 완료 건만 있다** → 동 단위 분석은 MVP에서 하지 않는다.
4. **최근 데이터는 계속 바뀐다.** 신고 기한(계약 후 30일), 해제 신고, 등기일 추가 때문에 최근 몇 개월은 재수집이 필요하다 → 증분 갱신은 "최근 N개월 재수집 + upsert" 구조 후보.
5. **실거래가 공개시스템은 자동 수집 금지** → 수집 경로는 공공데이터 API로 한정.

## 공공데이터 충분성 검토

| 필요 | MVP 필요 여부 | 소스 | 판단 |
|---|---|---|---|
| 거래 / 가격 / 거래량 / 해제 / 신고가 | 필수 | 실거래 상세 API | 충분 |
| 지역 계층 (시도 → 시군구 → 법정동) | 필수 | 행정표준코드관리시스템 법정동코드 (code.go.kr) | 추가 수집 필요 (파일 1회) |
| 단지 메타 (세대수, 동수, 단지 주소) | 선택 | 국토부 공동주택 단지 목록 / 기본정보 서비스 (K-apt 계열, ⚠️ 확인) | Phase 3 후보. `aptSeq` ↔ K-apt 단지코드 매칭이 별도 문제 |
| 공급면적 / 평형 | 선택 | 원천 없음 (단지 메타에 일부 가능성) | 표기 안 함 (02 결정 #3) |
| 좌표 | 지도용 | 지오코딩 (VWorld 등) | 지도와 함께 Phase 3 |
| 매물 호가 / 시세 | 없음 | 공공데이터 없음 | 범위 밖 (실거래 탐색 서비스) |

결론: **MVP는 실거래 상세 API + 법정동 코드로 충분하다.**

시군구 코드 개편 문제는 실측 결과 API가 과거 거래를 현재 코드로 돌려주므로 해소 (아래 실측 섹션).

## 실측: 마포구(11440) 2005-01 ~ 2026-10 (2026-10-14)

수집: 261회 호출, 에러 0, 평균 응답 0.18s (최대 1.67s). 탐색용 스크립트는 프로젝트 밖 임시 폴더에서 실행.

### 규모

- **52,871건**, 단지(`aptSeq`) 358개
- 연도별: 2006 3,382 / 2015 4,521 / 2021 1,563 / **2022 485** / 2025 4,270 — 시장 상황에 따라 10배 가까이 변동
- 월 최대 741건 → 마포구는 pagination 불필요. 단, 경기 대형 시군은 1,000건/월 초과 가능 → pagination 처리는 필수
- 데이터 시작: 사실상 **2006-01** (2005-11에 2건 존재)
- 크기: XML 약 835 bytes/row, 값만 약 260 bytes/row

### 필드 제공 시작 시점 — 기능 설계에 직접 영향

| 필드 | 제공 시작 | 영향 |
|---|---|---|
| `cdealType`, `cdealDay` (해제) | **2020-02** | 그 이전 거래는 해제 여부를 알 수 없다 → 해제 필터 / 신고가 계산 시 UI에 명시 필요 |
| `dealingGbn` (중개/직거래) | 2021-11 | 직거래 필터는 최근 데이터에만 의미 |
| `rgstDate`, `aptDong` | 2023-01 | 등기 여부 / 동 정보는 최근만 |
| `buyerGbn`, `slerGbn` | 2024-01 | MVP에서 사용하지 않음 |

빈 값은 `" "`(공백 한 칸)으로 온다 → trim 후 null 처리.

### 단지 식별 (`aptSeq`)

- 채움률 **100%** (전 기간)
- 하나의 `aptSeq`가 여러 이름 / 지번 / 건축년도를 갖는 경우: **0건**
- 반대로 사용자가 "한 단지"로 인식할 수 있는 것이 여러 `aptSeq`로 나뉜 경우가 있다
  - 마포래미안푸르지오 1~4단지 → 4개 (실제 단지 구분, 정상)
  - 공덕SK리더스뷰 → 2개 (도로명 번지가 다름)
  - 마포자이더센트리지 → 일반 동 / 임대 동 분리
- 결론: **`aptSeq`를 단지 ID로 그대로 사용할 수 있다.** 이름 기반 정규화는 필요 없고, "사용자 인식 단위로 묶기"는 선택적 개선 과제가 된다. (다른 시군구, 특히 오래된 데이터에서 재확인 필요)

### 거래 고유 키가 없다

- 거래 ID 필드가 없다.
- 같은 (단지, 계약일, 면적, 층, 금액) 조합이 2건 이상인 그룹: 657개
  - 해제 건 + 재신고 건 쌍 (해제 / 등기 / 동 필드만 다름): 다수
  - **모든 필드가 완전히 같은 행: 214그룹** — 같은 날 같은 층 같은 가격의 다른 동 거래일 수 있어 중복인지 구분 불가
- 결론: 내용 기반 dedupe를 하면 실제 거래를 지울 수 있다. 적재의 멱등성은 **(시군구, 계약년월) 단위로 통째로 교체**하는 방식이 후보.

### 면적

- 단지당 원본 전용면적 값 평균 4.4개, 최대 18개
- 1㎡ 미만 차이의 인접 값이 189개 단지에서 437쌍 (예: 84.86 / 84.87 / 84.95 / 84.96)
- 같은 "84 타입"으로 보이는 값과 실제로 다른 타입(57.88 vs 58.71)이 섞여 있다 → 면적 타입 그룹핑 규칙 필요 (5단계)

### 기타

- 금액: 콤마 포함 문자열, 단위 만원. 최소 2,000 / 최대 510,000
- 층: 음수(지하) 9건 존재
- `landLeaseholdGbn`: 전부 N (토지임대부 없음)

## 실측: 수도권 시군구 코드와 2025년 규모 (2026-10-14)

### 법정동 코드 소스

- 공공데이터포털 "국토교통부_전국 법정동" CSV (https://www.data.go.kr/data/15063424/fileData.do)
- 로그인 / 키 없이 스크립트로 다운로드 가능, UTF-8, 20,561행
- 컬럼: 법정동코드, 시도명, 시군구명, 읍면동명, 리명, 순번, 생성일자
- **현재 유효한 코드만 있다** (폐지 코드 없음)

### 행정구역 개편과 API 동작

- 수도권 시군구 단위 코드 91개 = 상위 시 코드 8개(수원·성남·안양·부천·안산·고양·용인·화성) + **조회 대상 83개**
- 상위 시 코드(예: 41110 수원시)로 조회하면 0건 → 일반구 코드로 조회해야 한다
- 최근 개편: 인천 중구·동구·서구 → 제물포구·영종구·서해구·검단구, 화성시 일반구 4개 신설, 부천시 일반구 재설치
- **API는 과거 거래도 현재 코드로 돌려준다.** 2008-03 / 2018-03 / 2025-01 모두 옛 코드(28110, 28140, 28170, 28260, 41190, 41590)는 0건, 새 코드에 데이터가 있다.
  → 현재 코드 83개만 조회하면 전체 기간을 일관된 지역 단위로 받을 수 있다. 히트맵 행 구성 문제가 사라진다.
- **`aptSeq`는 옛 코드를 앞자리로 유지한다** (예: 화성 동탄구 단지 `41590-…`, 인천 제물포구 단지 `28110-…`, `28140-…`)
  → 행정구역 개편에도 단지 ID가 안정적이다. URL ID로 적합.
  → `aptSeq` 앞자리로 지역을 판단하면 안 된다. 지역은 `sggCd`를 사용한다.
- 주의: 앞으로 또 개편되면 이미 저장된 데이터의 `sggCd`가 API와 달라진다 → 개편 시 전체 재수집 또는 코드 매핑 필요.
